The read-only brain for your infrastructure

Infra Brain continuously inventories, documents, and detects drift across your estate — and when something's wrong it proposes a fix. It never changes infrastructure itself. Think of it as a tireless auditor that keeps your CMDB and runbooks true to reality.

● Read-only on all infrastructure ✎ Only 4 write paths: its DB · GitLab MR · Jira · Confluence ⛨ Propose, never dispose

01The mental model

One idea unlocks everything else: Infra Brain is a hybrid. Fast deterministic collectors do the routine read-only gathering; an LLM reasoning layer handles the judgement work — and every tool the LLM touches is forced through the same read-only safety checks.

02Architecture, in three diagrams

If you remember three pictures, remember these: how a sweep flows, how the LLM is kept on a leash, and the complete map of what can write where.

A · Collection & drift pipeline (the heartbeat)

Scheduler / webhook / POST /sweeps/{domain}→ Supervisor routes to the domain agent→ Agent collect() — read-only→ Upsert resources + write snapshots
↳Post-hook: DriftDetector diffs vs last snapshot→ drift? → Jira ticket + Confluence page + GitLab MR

Redis token-locks each domain so two sweeps can't overlap. Every tool call is recorded to agent_action_log.

B · The enforced LLM tool path (why the AI can't go rogue)

LLM agent reason()→ bind read-only tools→ invoke with callback chain→ ReadOnlyToolValidator · DLP · Audit→ tool runs · result fed back

The callback chain rides on every invoke (config={"callbacks": …}). A blocked call raises PermissionError, which is handed back to the model as a tool message — it learns it can't, instead of crashing. Decisions are logged to agent_decision_log.

C · The complete write map (everything else is read-only)

Infra Brain → ① Postgres (own DB) ② GitLab MR ③ Jira ④ Confluence

Those four arrows are the only places code mutates anything. All infrastructure systems (vSphere, GitLab repos, Octopus, Rapid7, cloud, k8s, hosts) are reached with GETs exclusively. planned a memory/retrieval layer will sit beside Postgres — see Accuracy.

03The six workflows

Almost everything Infra Brain does is one of these. Each is triggered, runs a few steps, and produces a concrete result.

Collection sweep deterministic

The heartbeat. Keeps the inventory current.

schedule / POST /sweeps/{domain}→collect (read-only)→upsert + snapshot→drift check

Cadence: most domains every 6h; cloud/cicd/octopus/vuln/eol daily.

Drift → propose, never dispose core

Reality diverged from the record — so it raises it, never silently fixes it.

snapshot differs→DriftDetector (DeepDiff)→Jira + Confluence→GitLab MR (human merges)

Inventory fixes go out as a branch + commit + MR — a person approves the merge.

Autonomous discovery LLM

"Spread out and find what we don't yet track."

weekly (Sun)→reason over read-only tools→findings / proposals

Cross-references sources (e.g. host in Ansible but not the DB). No write tools in its kit.

Self-improvement loop LLM

It gets better at watching the things that actually move.

weekly→DriftLearning → Instincts→read back into prompts→smarter runs

Generated scripts saved to DB + Git (deduped, reusable, never deleted). Actions and decisions logged.

Ask it questions LLM

Natural-language Q&A over the live inventory.

UI chat→NL-to-SQL (read-only)→answer from Postgres

"How many Windows hosts are EOL?" — the SQL it runs is blocked from mutating anything.

Script-assisted gathering optional · off by default

When a built-in tool can't reach a fact, it can write a read-only script.

enabled + asked→generate PS/Py/Bash→deny-list + sandbox + audit→output + saved script

Disabled unless scripts_enabled=true. See the guardrail caveat below.

04How to interact with it

There are four ways you'll touch the agent day to day. You rarely need the API — most work happens in the UI.

💬 The chat (most common)

In the Streamlit UI sidebar, ask in plain English. It translates to read-only SQL over the inventory and answers from real rows.

"Which hosts haven't reported in 7 days?"
"List Octopus tentacles that are offline."
"What changed on the core firewall this week?"

Trust it because: read-only, grounded in the DB, and every query is audited.

🖥 The dashboards

Browse without asking. Each page is a live view of one slice:

  • Home — fleet health at a glance
  • Resources / Drift Events / Collection Runs — the inventory + what changed
  • Integration Proposals — approve/decline new coverage
  • Instincts · Agent Activity · Decisions · Generated Scripts — the brain's memory & audit trail

⚡ Trigger work (API)

Kick an immediate sweep instead of waiting for the schedule:

POST /sweeps/{domain}
  header: X-Infra-Token: <secret>   # if configured

# 409 = a sweep for that domain is already running

Inbound webhooks (/webhooks/gitlab|octopus|ansible|…) let your tools nudge it on change.

📥 Consume its output

You don't always go to the agent — it comes to you:

  • Jira tickets when drift needs action
  • Confluence pages kept current automatically (your living docs)
  • GitLab MRs proposing inventory corrections — review & merge
  • LangSmith traces (if enabled) for deep "why did it do that?"

Command-level detail (env vars, install, every endpoint) lives in docs/USER_GUIDE.md — this page stays conceptual.

05Guardrails — why you can trust it

The safety model is layered and, crucially, enforced in code — not just convention. Internalise this before you let it run.

✓

Read-only by construction and enforcement

Collectors only issue GETs. The LLM can't cheat: ReadOnlyToolValidator blocks mutating HTTP / SQL / Ansible, attached to every tool call.

4

Exactly four write paths

Postgres, GitLab MR, Jira, Confluence. No other code path mutates anything, anywhere.

⛨

Propose, never dispose

Versioned-infra changes leave as MRs a human reviews. The agent never pushes to a default branch.

✋

Approval gates

integration_approval_required holds new integrations / cadence changes for a human.

🔑

Webhook authentication

Shared-secret, constant-time compared. webhook_auth_required=true fails closed when a secret is missing.

🛡

DLP redaction

Tool I/O scanned for cards / secrets and redacted; can be fail-closed.

🔒

De-duplicated runs

Redis token-locks per domain — no overlapping sweeps (409 / scan pending).

📓

Full auditability

Every action, every LLM decision, plus optional end-to-end LangSmith traces.

⚠ One honest caveat — script execution. The script runner is a deny-list filter, not a jail. It ships off by default (scripts_enabled=false). Its real boundary is being gated-off plus a non-root container — keep it disabled unless you're isolated and understand the trade-off.

06Accuracy & hallucination prevention

For an audit/documentation agent, a confidently wrong fact is worse than a gap. The architecture is anti-hallucination by design — and we lean into that.

The structural defense (already true)

  • Facts are scraped, not generated. The LLM never invents infra facts — deterministic collectors produce the truth; the model only reasons over real data.
  • Drift narratives are grounded in a real diff. The model summarizes actual DeepDiff output that's in its context.
  • Discovery requires evidence. Findings are structured JSON with a cited evidence source — no source, no finding.
  • The LLM is a reasoner over retrieved facts, never a knowledge source.

The practices we apply / are tightening

  • Chat returns its receipts — the SQL it ran + the actual rows, so answers are auditable, and "no matching data" instead of a guess.
  • Structured outputs (schemas) constrain what the model may say.
  • Low temperature on factual paths; verification pass before high-stakes writes (a ticket or MR).
  • Bounded, relevant context — only the facts a step needs are put in front of the model.
↗ Coming: a retrieval (RAG) memory layer. A vector index over the agent's own accumulated text — Confluence pages, past drift narratives, reusable scripts, instincts, runbooks — will (a) make the self-improvement loop's reuse semantic ("seen a drift like this before?") and (b) ground chat/discovery answers in retrieved evidence to cut hallucination further. It's a memory for the unstructured knowledge; the structured inventory stays in SQL. Design in progress — pgvector vs Qdrant under evaluation.

07Performance — where time & cost go

Two different budgets: wall-clock (dominated by API round-trips) and tokens (dominated by the LLM paths). They're tuned separately.

I/O-bound
Sweeps are mostly network round-trips to GitLab / Octopus / vSphere / Rapid7 — not CPU.
LLM = cost
Discovery, drift-learning & chat drive token spend; routine reasoning can run on a cheaper model.
Indexed
Hot query paths have DB indexes; Redis dedup prevents pile-ups.

Wall-clock levers

  • Concurrent collection within an agent (async + bounded fan-out) — the biggest single win on heavy domains.
  • Stagger cadences so domains don't all fire on the same minute.
  • Batch DB writes per run instead of per item.
  • Conditional fetch (ETag / version) to skip unchanged resources.

Token / cost levers

  • Cheap model for routine reasoning; reserve the top model for hard synthesis.
  • Prompt caching for the stable schema/system preamble.
  • Cap reasoning iterations (already bounded) and keep injected context tight.
  • Semantic reuse (the coming RAG layer) avoids re-deriving what's already known.

None of these change the architecture — they're tuning knobs. Expect the rhythm in Results: 6-hourly for most domains, daily for heavy APIs, weekly for the LLM-driven jobs.

10Glossary & pointers

Drift
A difference between the latest snapshot and the prior one — reality changed.
Snapshot
A point-in-time capture of a resource's config/state, diffed for drift.
Instinct
A learned heuristic read back into future reasoning.
Observation
A record of which tools an agent used — feeds learning context.
Scan point
A scheduled collection entry for a domain.
Propose, never dispose
Fixes go out as reviewable MRs/tickets, never direct infra changes.
RAG / retrieval (planned)
Semantic search over the agent's accumulated text to ground answers & reuse.
Hybrid layer
Deterministic collectors + an enforced LLM reasoning layer, side by side.
